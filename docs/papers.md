# Research behind miniserve

miniserve re-implements the **core algorithms** of published LLM-serving research in PyTorch, validated against a reference implementation and benchmarked. It does **not** reproduce the original systems' custom CUDA kernels or scale. This page maps each component to its source and says what is implemented and what is not. (arXiv identifiers are given where I am confident of them; check any you intend to cite formally.)

| Component | Source | What the source contributes | What miniserve implements | What it does not |
|---|---|---|---|---|
| Model | **Attention Is All You Need** (Vaswani et al., 2017); **RoPE** (Su et al., arXiv 2104.09864); **GQA** (Ainslie et al., arXiv 2305.13245); **RMSNorm** (Zhang & Sennrich, 2019); **SwiGLU** (Shazeer, 2020) | The architecture of modern decoder-only LLMs | A from-scratch Qwen2 forward pass verified against Hugging Face | Training; custom kernels |
| KV cache | Standard practice | Reuse past keys/values while decoding | Preallocated cache, prefill/decode, positions and masks | Cache eviction/compression |
| Continuous batching | **Orca** (Yu et al., OSDI 2022) | **Iteration-level scheduling**, selective batching | Per-step scheduler over a slot cache with per-row positions and masks; static and sequential baselines | Distributed execution; selective batching of ragged tokens (padding + masks are used) |
| Paged KV cache | **Efficient Memory Management for LLM Serving with PagedAttention** / vLLM (Kwon et al., SOSP 2023, arXiv 2309.06180) | **Block-based KV cache**, block tables, copy-on-write, preemption, the vLLM system | Block pool, block tables, reference counts, LRU eviction, **hash-chained prefix caching**, recompute preemption | The PagedAttention CUDA kernel (a gather is used), copy-on-write, swapping |
| Prefix sharing (related) | **SGLang / RadixAttention** (Zheng et al., arXiv 2312.07104) | Radix-tree prefix sharing | Block-granular hashing instead | Radix tree |
| Speculative decoding | **Leviathan et al.** (ICML 2023, arXiv 2211.17192); **Chen et al.** (arXiv 2302.01318) | Draft-then-verify decoding that preserves the target distribution | Exact speculative sampling (acceptance rule + residual correction, greedy and sampled), a draft-model drafter and a prompt-lookup n-gram drafter, one-pass verification, KV rollback, statistical exactness tests, a speedup model checked against measurements | Tree-based speculation (Medusa, EAGLE, SpecInfer), trained draft heads, adaptive k, combination with batching/paging |
| Quantization | **LLM.int8()** (Dettmers et al., arXiv 2208.07339); **GPTQ** (Frantar et al., arXiv 2210.17323); **SmoothQuant** (Xiao et al., arXiv 2211.10438); **AWQ** (Lin et al., arXiv 2306.00978) | Low-bit weights and activations with outlier handling | Round-to-nearest int8/int4/int3 (per-tensor, per-channel, group-wise, asymmetric, packed int4); **GPTQ** (Hessian, Cholesky, blocked error compensation); W8A8 and **SmoothQuant** (simulated); int8 KV cache with static per-channel key scales; perplexity protocol; outlier diagnostics | Fused int4/int8 kernels (so no speed claim), AWQ, LLM.int8 mixed-precision decomposition, fp8, downstream-task evaluation |
| Launch-overhead removal | **CUDA Graphs** (NVIDIA); used by vLLM for decoding | Record a whole step once, replay it with one launch | A static-shape decode path (`StaticSlotBatch`) and a graph runner capturing one graph per batch size, with padding rows parked in a scratch slot; measured 3.1-4.2x faster decode steps on an A10 | Graphs for the paged engine, for prefill, or for the speculative drafter; piecewise capture |
| Attention kernel (context) | **FlashAttention** (Dao et al., arXiv 2205.14135) | IO-aware exact attention | Used through PyTorch SDPA | Writing the kernel |
| Prefill scheduling (context) | **Sarathi / chunked prefill** (Agrawal et al., arXiv 2308.16369); **DistServe** (Zhong et al., OSDI 2024); **Splitwise** (Patel et al., 2024) | Mixing or disaggregating prefill and decode | The mask path supports chunked prefill, but no chunked-prefill scheduler | Chunked-prefill scheduler, disaggregation |
| Long streams (context) | **StreamingLLM** (Xiao et al., arXiv 2309.17453) | Attention sinks for endless streams | Observed the related effect (first-token "massive activations") in quantization diagnostics | Implementation |

## How to describe this accurately
- **Accurate:** "Implemented the continuous-batching scheduler of Orca and the paged KV-cache memory manager with prefix caching of vLLM in PyTorch, validated against a reference implementation, and measured on CPU and an A10 GPU."
- **Not accurate:** "Reproduced vLLM" or "built PagedAttention". The kernel is the hard part of PagedAttention and was not written here.
