# 1.6 RoPE: how attention knows word order

**Goal:** explain why attention needs position information, how rotary embeddings (RoPE) inject it, and why the result is
*relative* position. You should be able to defend each step with the numbers below.

## The problem
Attention (1.3) is a weighted average over a *set* of tokens. Nothing in it says which came first.
"Dog bites man" and "Man bites dog" would produce the same attention scores. We must add position information.

Older approaches: add a learned or sine vector per position to the token embedding (GPT-2, original Transformer).
RoPE (Su et al. 2021, used by Llama, Qwen, Mistral) does something neater.

## The clock-hand picture
Take a query (or key) vector with 64 numbers and group them into **32 pairs**. Each pair `(a, b)` is a point in a 2D plane,
like the tip of a clock hand. **Rotate each pair by an angle proportional to the token's position.**

Toy: rotate `[1, 0]` by 90° per position:
```
pos 0: [ 1,  0]    pos 1: [ 0, 1]    pos 2: [-1, 0]    pos 3: [ 0, -1]
```
Rotation is applied to **Q and K only** (not V), because position matters for *deciding who matches whom*, not for the content
handed over.

## The key property: only relative distance survives
The attention score is `q · k`. Rotating q by angle α and k by angle β and then taking the dot product gives a result that
depends only on `α − β`, the **difference in angles**, which is `(position difference) × frequency`.

Real function, one rotating pair (`python examples/lesson1_demos.py 1.6`):
```
q at pos   5, k at pos   3 (distance 2): q·k = 0.3477
q at pos  12, k at pos  10 (distance 2): q·k = 0.3477
q at pos 100, k at pos  98 (distance 2): q·k = 0.3477
q at pos   7, k at pos   3 (distance 4): q·k = -0.6994
```
Same distance → identical score, regardless of where in the text. The model gets "that word is 2 positions back"
for free, and it generalizes across positions.

## Many speeds, like a clock
Each of the 32 pairs rotates at its own frequency:
`freq_i = 1 / theta^(2i/64)`, with `theta = 1,000,000` for Qwen.
```
fastest pair: 1.00 radian per token      slowest pair: 0.0000015 radian per token
```
Fast hands resolve small distances precisely (like a second hand) but wrap around quickly. Slow hands barely move
over thousands of tokens and capture long range (like an hour hand). Together they give a unique, multi-scale "address"
of position. A bigger `theta` (Qwen's 1e6 vs original 1e4) makes the slow hands even slower, which helps long contexts.

## In our code
[model.py:71-93](../../src/miniserve/model.py#L71-L93):
- `rope_cos_sin(positions, ...)` computes `cos(pos × freq)` and `sin(pos × freq)` for every position and pair.
- `apply_rope`: `x * cos + rotate_half(x) * sin` is exactly the 2D rotation formula `(a cos − b sin, a sin + b cos)`.
- The pairing: this implementation pairs feature `i` with feature `i + 32` (the "rotate-half" convention, matching Hugging Face
  weights), not neighbouring features. Same math, different layout. Using the wrong convention gives garbage, which
  is why our parity test matters.
- `positions` is a parameter, not derived from sequence length. **This matters for the KV cache:** when generating token
  number 501 we must tell the model "this token is at position 500", not "position 0".

## Why this is cache-friendly
A token's rotation depends only on *its own* absolute position. Its cached key was rotated once when computed and
never needs to change. (Contrast with schemes that re-encode relative offsets at attention time.)

## Interview ladder
**Level 1: Why do transformers need positional encoding?**
Attention is order-agnostic; without position info, shuffled input gives shuffled but otherwise identical results.

**Level 2: How does RoPE work?**
Rotate pairs of query/key features by angles proportional to the token's position, each pair at a different frequency. The dot
product then depends only on the relative offset.

**Level 2: Why apply to Q and K but not V?**
Position affects *matching*, which is computed from q·k. V is content that gets averaged; rotating it would corrupt the information
being transported.

**Level 3: Why is RoPE good for KV caching?**
Each key is rotated by its own absolute position once; the cached key stays valid as the sequence grows. Relative information
emerges at attention time automatically.

**Level 3: Can the model handle longer sequences than it was trained on?**
Not reliably: angles it never saw during training are out of distribution. Extensions rescale positions or frequencies
(position interpolation, NTK scaling, YaRN) and usually fine-tune briefly. Qwen2.5-0.5B is configured for 32k context.

**Level 3: What does a larger `theta` do?**
It lowers all frequencies (slower rotation), stretching the range of distinguishable positions, which suits long-context models.
