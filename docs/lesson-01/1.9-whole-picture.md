## The forward pass in one view

```
"The capital of France is"
   │ 1.1 tokenizer                      5 ids: [785, 6722, 315, 9625, 374]
   ▼
embedding lookup (1.2)                  (1, 5, 896)
   │
   ▼  ┌── repeat 24 times (1.7) ────────────────────────────────────────┐
   │  │ x ← x + Attention(RMSNorm(x))                                   │
   │  │        Q: 14 heads × 64     K,V: 2 heads × 64  (GQA, 1.5)       │
   │  │        RoPE on Q,K (1.6) → scores QKᵀ/√64 → causal mask (1.4)   │
   │  │        → softmax → × V → o_proj                                 │
   │  │ x ← x + MLP(RMSNorm(x))    SwiGLU 896 → 4864 → 896              │
   │  └─────────────────────────────────────────────────────────────────┘
   ▼
final RMSNorm → lm_head (tied to embeddings) → logits (1, 5, 151936)
   │ take the last position (1.8)
   ▼
softmax → pick (greedy/temperature/top-p) → " Paris" → append → repeat
```

## The two-minute answer (practice this out loud)
> "It's a decoder-only transformer. Text is tokenized with byte-level BPE into ids, which index an embedding table to give
> 896-dimensional vectors. Those pass through 24 identical layers. Each layer has two residual sublayers with RMSNorm before each:
> causal self-attention, where every token computes a query, key and value, rotary position embeddings are applied to queries and keys,
> and each token takes a softmax-weighted average of earlier tokens' values; and a SwiGLU MLP applied per token. Qwen uses grouped-query attention,
> 14 query heads sharing 2 key/value heads, to shrink the KV cache 7×. A final norm and a linear head, tied to the embedding matrix, produce logits
> over about 152k tokens; softmax with temperature or top-p picks the next token, which is appended and the process repeats. I implemented this from
> scratch and verified the logits match Hugging Face within 1e-3."

## Mixed-topic drill (the ones interviewers love)
1. **"Walk me through what happens when I send a prompt."** Use the two-minute answer, then add prefill vs decode (1.4).
2. **"Why is LLM inference slow and what limits it?"** Autoregressive: one forward pass per token. Decode is memory-bandwidth-bound, since every token
   streams all weights (and the KV cache) from memory.
3. **"Where does the memory go when serving?"** Weights (about 1 GB bf16) + KV cache (12 KB/token/sequence here) + activations. At high concurrency the
   KV cache dominates, which is why GQA, quantizing the cache and paged allocation matter.
4. **"Why can we cache K and V but not Q?"** New token needs the old K,V; old tokens' queries are never reused. Causal mask means old K,V never change,
   and RoPE rotates each token by its own absolute position.
5. **"Which operations are compute-bound and which memory-bound?"** Prefill: big matmuls, compute-bound. Decode: tiny matvecs, memory-bound.
6. **"How would you verify an optimization did not change model outputs?"** Greedy decode both ways and compare token ids exactly; compare logits within tolerance.
   That is our parity test plus the tests we add in each stage.
7. **"What would you change to support a 100k-token context?"** RoPE scaling (YaRN), more KV memory per sequence (GQA/quantized KV/paging), flash attention.

## Loader details interviewers may probe
- **Why build on the `meta` device?** It creates the module structure with shapes only and no memory, so we don't allocate 2 GB of random
  weights just to overwrite them.
- **What does `assign=True` do?** Uses the loaded tensors directly instead of copying values into existing parameters.
- **Why `strict=False`?** The checkpoint has no separate `lm_head.weight` (tied), so one key is legitimately absent; we re-tie it explicitly afterwards.
- **Why did the parity test use fp32?** To compare exactly. bf16 comparisons need a looser tolerance because of its coarse precision.
