# 1.8 Logits, softmax and sampling

**Goal:** explain how the final vector becomes a chosen word, what temperature / top-k / top-p do, and learn two cost facts
about the output layer that we will exploit in later stages.

## From vector to scores
After 24 layers and a final RMSNorm, each position has an 896-number vector. The `lm_head` (1.2) turns it into **one score per vocabulary
entry: `logits`, shape `(T, 151936)`**. Logits are raw: any real number, not probabilities.

**For generation only the *last* position matters.** Position `T-1` predicts token `T`. The other `T-1` rows are used only in training.

## Softmax: scores → probabilities
`softmax(z)_i = exp(z_i) / Σ exp(z_j)`. Real result from the walkthrough for "The capital of France is":
```
' Paris' 30.2%    ' ______' 12.3%    ':\n' 6.6%    ':\n\n' 5.8%    ' __' 4.8%
```
The model is distributing belief, not stating a fact. 30% means it's far from sure.

## Choosing a token (decoding strategies)
- **Greedy:** take the argmax. Deterministic. Can be repetitive.
- **Sampling:** draw randomly according to the probabilities. More varied.
- **Temperature `T`:** divide logits by `T` *before* softmax. Real demo, logits `[2,1,0,-1]`
  (`python examples/lesson1_demos.py 1.8`):
  ```
  T=0.5: [0.865, 0.117, 0.016, 0.002]   sharper, more confident
  T=1.0: [0.644, 0.237, 0.087, 0.032]   as trained
  T=2.0: [0.455, 0.276, 0.167, 0.102]   flatter, more random
  ```
  As `T → 0` it becomes greedy; as `T → ∞` it becomes uniform random.
- **Top-k:** keep only the k highest-probability tokens, renormalize, sample.
- **Top-p (nucleus):** keep the smallest set of top tokens whose cumulative probability reaches p (e.g. 0.9), renormalize, sample.
  In the demo sorted probs `[0.644, 0.237, 0.087, 0.032]` have cumulative `[0.644, 0.881, 0.968, 1.0]`, so top-p 0.9 keeps 3 tokens. It adapts: few
  candidates when the model is confident, many when it's unsure. Top-k can't do that.

## Stopping
Generation ends when (a) the end token (`<|im_end|>`, id 151645) is produced, or (b) `max_tokens` is reached. Forgetting (a) makes the
model ramble after finishing its answer.

## Two cost facts for later
1. **Wasted work in prefill.** Computing logits for every prompt position builds a `(T, 151936)` tensor. For a 1,000-token prompt in fp32 that is
   `1000 × 151936 × 4 bytes = 608 MB` of logits we throw away, plus 136M × 1000 multiply-adds. Fix: slice the final hidden state to the last position
   *before* `lm_head`. We'll do this in the cached `generate` in Lesson 2, and measure it.
2. **Greedy is special for verification.** At temperature 0 the output is deterministic, which makes it easy to *prove* that an optimization
   (KV cache, batching) did not change results: outputs must be identical token for token. We use this in every test. Speculative decoding
   (Stage 5) handles non-greedy sampling with a cleverly corrected acceptance rule.

## Interview ladder
**Level 1: How does an LLM pick the next token?**
Final hidden state → linear head → logits over vocabulary → softmax → select (argmax or sample).

**Level 2: What does temperature do mathematically?**
Divides logits before softmax: T<1 sharpens the distribution, T>1 flattens it, T→0 is greedy.

**Level 2: Top-k vs top-p?**
Top-k fixes the number of candidates; top-p fixes the probability mass kept, so candidate count adapts to the model's confidence.

**Level 3: Why might greedy decoding give repetitive text?**
Always taking the mode can lock into loops: once a phrase repeats, the context makes repeating more likely. Sampling or repetition penalties break it.

**Level 3: Is temperature 0 truly deterministic on a GPU?**
Not always bit-for-bit: floating-point reductions can vary with batch size, kernel choice and thread scheduling, so near-tied logits can flip.
This is a real gotcha when testing batched vs unbatched outputs.

**Level 3: In prefill, why compute logits only for the last token?**
Only that position produces the next token. The rest would waste compute and memory proportional to prompt length × vocab size.
