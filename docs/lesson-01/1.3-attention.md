# 1.3 Attention (Q, K, V)

**Goal:** be able to compute attention by hand on a tiny example, and explain every symbol in
`softmax(QKᵀ/√d)V`. This is the most important segment in the lesson. Lesson 2 (KV cache) is built on it.

## The problem attention solves
In *"The animal didn't cross the street because **it** was too tired"* the word "it" must pull in
information from "animal". Each token needs a way to **look at other tokens and copy useful information**.
That is attention.

## Three roles, one token
Each token's vector `x` is multiplied by three different learned matrices to make three vectors:

| Vector | Made by | Role | Analogy |
|---|---|---|---|
| **Query (Q)** | `x · W_q` | "What am I looking for?" | the question you bring to a library |
| **Key (K)** | `x · W_k` | "What do I offer / what am I about?" | the label on a book's spine |
| **Value (V)** | `x · W_v` | "What do I hand over if chosen?" | the contents of the book |

Why separate K and V? *What makes a token relevant* (match on K) is not always the same as *what
information it should contribute* (V). Separating them lets the model learn both.

## The four steps
For one token with query `q`, and keys/values of all tokens it may look at:

1. **Score:** `score_i = q · k_i` (dot product: big when vectors point the same way = good match)
2. **Scale:** divide by `√d` (d = size of q, here 64)
3. **Softmax:** turn scores into weights that are positive and sum to 1
4. **Blend:** `output = Σ weight_i × v_i`

Compactly: **`Attention(Q,K,V) = softmax(Q Kᵀ / √d) V`**.

## Worked example you can do on paper
Three tokens, 2 numbers each. Our query is `q = [1, 0]`.
```
K1 = [1,0]   K2 = [0,1]   K3 = [1,1]
V1 = [10,0]  V2 = [0,10]  V3 = [5,5]
```
Run `python examples/lesson1_demos.py 1.3` to check yourself.

1. Scores `q·K`: `[1, 0, 1]` ([1·1+0·0], [1·0+0·1], [1·1+0·1])
2. Divide by √2 = 1.414: `[0.707, 0, 0.707]`
3. Softmax: `exp(0.707)=2.03, exp(0)=1, exp(0.707)=2.03`, total 5.06, so weights `[0.401, 0.198, 0.401]`
4. Output = `0.401·[10,0] + 0.198·[0,10] + 0.401·[5,5]` = **`[6.02, 3.98]`**

Meaning: the query matched K1 and K3 equally and K2 weakly, so the output is mostly a blend of V1 and V3.

## What softmax does
`softmax([2,1,0]) = [0.665, 0.245, 0.090]`. Exponentiate each score, then divide by the total. Properties:
all outputs positive, they sum to 1, bigger scores get disproportionately more weight. It is a "soft"
version of "pick the max".

## Why divide by √d?
Dot products of d-dimensional vectors grow with d. Measured:
```
d=4    : std(q·k) = 1.98   after /√d: 0.99
d=64   : std(q·k) = 7.96   after /√d: 1.00
d=1024 : std(q·k) = 32.15  after /√d: 1.00
```
Large scores push softmax into saturation: `softmax([20,10,0]) = [0.99995, 0.00005, 0]`, essentially
"pick one, ignore all others". In that regime gradients vanish and the model can't learn well. Dividing by √d keeps
the spread near 1 whatever d is.

## Matrix form (what the code does)
For T tokens at once, Q, K, V are matrices of shape `(T, d)`. `Q Kᵀ` is a `(T, T)` table of scores: row i = how much token i
wants each token j. That table is what we printed in lesson 1's walkthrough. Softmax each row, multiply by V, done.
Compute cost grows as **T²** (every token against every token). This is why long contexts are expensive.

## In our code
[model.py:108-125](../../src/miniserve/model.py#L108-L125):
- `self.q_proj / k_proj / v_proj` are `W_q, W_k, W_v`. Notice they have `bias=True` in Qwen.
- `F.scaled_dot_product_attention(q, k, v, is_causal=True)` performs steps 1–4 in one fused, optimized kernel
  (plus the mask, see 1.4). We use PyTorch's built-in instead of writing the T×T table by hand, since it avoids
  materializing the whole table in memory.
- `self.o_proj` mixes the result back (1.5).

## Interview ladder
**Level 1: Explain attention.**
Each token produces a query, key and value. Its query is compared with every other token's key to get
similarity scores; softmax converts them to weights; the output is the weighted sum of values. So every token can
gather information from the rest of the sequence.

**Level 2: Why separate keys and values?**
Relevance and content are different things. Keys are optimized for matching, values for what gets passed on.

**Level 2: Why the √d scaling?**
Dot product variance grows linearly with d, so scores get large, softmax saturates and gradients shrink. √d
normalizes the variance to about 1.

**Level 2: What is the time and memory complexity of attention?**
O(T²·d) compute and O(T²) memory for the score table in the naive version. FlashAttention-style kernels keep
compute but avoid storing the T×T table.

**Level 3: Which of Q, K, V would you need to store to avoid recomputation when generating the next token?**
K and V of all past tokens. The new token's query attends over them, and the old keys and values don't change.
Queries of old tokens are never needed again. **This single observation is the KV cache** (Lesson 2).

**Level 3: Is attention permutation-invariant?**
Without position information, yes: shuffling tokens shuffles outputs the same way and the model can't tell order.
Position encoding (RoPE, 1.6) breaks this symmetry.
